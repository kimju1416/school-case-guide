# 사실 검수 규칙 (정확성이 생명)

대상: `research/<id>.json` (교사용 공개 사이트 «학교 사안 처리 길잡이»의 내용). 오늘 2026-09-24.
형식은 `_SCHEMA.md` 참고. **다른 검수원도 동시에 다른 파일을 고치고 있으니, 맡은 파일만 고친다.**

## 무엇을 검수하나
파일 안의 **모든 사실 주장**. 특히:
1. 숫자: 기한·일수·시간·기간(기산점 포함 — «안 날부터 / 있은 날부터 / 통지받은 날부터»), 금액(과태료·벌금 상한), 인원·횟수, 호수(1~9호 등)
2. 법령: 법률 이름·조·항·호 번호가 그 내용과 실제로 맞는지, **현재 시행 중인 조문**인지(개정·신설·삭제 확인)
3. 전화번호·기관 이름(최근 이름이 바뀐 기관 주의)
4. 법적 효과: «~해야 한다(의무)» vs «~할 수 있다(재량)», 처벌 여부, 면책 조건, 청구권자, 피청구인/피고
5. 절차 순서와 주체(누가 하는가 — 학교장/교육장/교육감/위원회)
6. 출처: 제목·발행기관·연도가 실제와 맞는지, 2021년 이후인지
7. deep·tables·faq·dont·first 안의 서술도 전부 포함

## 어떻게 확인하나
- 법령: 국가법령정보센터 현행 조문(law.go.kr). WebFetch가 안 되면 `curl --ssl-no-revoke -L`로 받아 읽는다. 법령 본문 API 예: `https://www.law.go.kr/DRF/lawService.do?OC=test&target=law&type=XML&MST=...` 대신 `https://www.law.go.kr/법령/<법령명>` 페이지나 `/LSW/lsInfoP.do` 등 가능한 방법을 쓴다. (research/src/ 에 이미 받은 법령 텍스트·매뉴얼 PDF 텍스트가 많다 — 먼저 거기서 grep)
- 매뉴얼: research/src/ 의 텍스트, 없으면 공식 게시처에서 받아 pdfplumber로 추출.
- **기억이나 짐작으로 «맞다»고 판정하지 않는다.** 원문 문장을 찾은 것만 «확인».

## 판정과 처리
- 확인됨 → 그대로 둔다.
- **틀림** → 원문대로 고친다(JSON 직접 수정). 근거 칸(basis)도 맞게 고친다.
- **확인 불가** → 본문에서 단정 표현을 빼거나 완화하고, 그 내용을 `uncertain`에 «…은 원문 확인 필요»로 옮긴다. 확인 안 된 숫자를 본문에 남기지 않는다.
- 새 내용을 추가하지 않는다(검수이지 보강이 아니다). 단, 틀린 것을 바로잡는 데 필요한 최소한은 괜찮다.
- 공개 사이트라 보호자·학생 응대 대본(script)은 넣지 않는다.
- 고친 뒤 JSON이 제대로 읽히는지 `node -e "JSON.parse(require('fs').readFileSync(f))"`로 확인.

## 기록
파일마다 `research/verify/<회차>-<id>.md`:
```
# <회차> <id> 검수 — 확인 N · 고침 N · 확인 불가 N
| 칸 | 원래 내용 | 판정 | 원문 근거(법령 조항 / 매뉴얼 쪽) | 고친 내용 |
```
«확인됨»은 한 줄씩 다 쓰지 않아도 되고 개수만 적어도 된다. «고침»과 «확인 불가»는 빠짐없이.
끝나면 짧게 보고: 파일별 확인/고침/불가 개수와, 고친 것 중 중요한 것(법적 효과·기한·번호가 바뀐 것).
